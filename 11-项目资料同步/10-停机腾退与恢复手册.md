## 二、恢复操作（按需）

### 2.1 一键恢复全部（标准 2 副本）

```bash
for d in agent-runtime event-consumer h5-member h5-store mcp-fnb-tools \
         ollama-fnb svc-forecast svc-inventory svc-member svc-portal \
         svc-procurement svc-recipe svc-worldmodel web-admin; do
  kubectl -n fnb-prod scale deploy/$d --replicas=2
done
# web-admin 单副本
kubectl -n fnb-prod scale deploy/web-admin --replicas=1
```

### 2.2 恢复定时任务

```bash
kubectl -n fnb-prod patch cronjobs alert-compute alert-push quality-check -p '{"spec":{"suspend":false}}'
```

### 2.3 数据层 cold-start 顺序（若公共依赖也重启过）

1. TiDB / Redis 集群确认 healthy；
2. Redis warmup：`kubectl -n fnb-prod delete job redis-warmup --ignore-not-found`
   `kubectl -n fnb-prod apply -f deploy/04-warmup-bench.yaml`（镜像 fnb/tools:0.3.2）；
3. db-init 仅首次部署需要（数据仍在 TiDB，勿重复执行避免清库）。

## 三、注意事项（历史教训沿用）

1. **永远不用 `kubectl set env` 改 Deployment**（会触发重建回滚镜像）；改配置一律 `apply -f` 或 `set image`；
2. `set image` 后须用 `imageID` 核对双节点 digest 一致（本轮曾出现 worker 缓存旧 digest 导致修复未生效）；
3. TiDB 数据（1.51 亿行）在 infra 命名空间，未受本次停机影响；
4. 恢复后首次对话较慢属正常（Ollama 模型冷加载 40-120s）。
