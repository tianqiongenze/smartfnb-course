# 《连锁餐饮智能体工程化项目实战》课程标准

> 依据：教育部高职高专专业教学标准、GB/T 8557 软件工程、GB/T 25000 软件质量、TOGAF 架构框架，并深度融合**德国双元制教育模式**、**费曼学习法**与**布鲁姆认知目标分类学**。
> 适用专业：人工智能技术应用 / 大数据技术 / 软件技术（高职高专）
> 课程性质：专业核心项目实践课（工学结合一体化）
> 课程代码：SNF-AI-201
> 参考学时：64 学时（理论 24 / 实践 32 / 考核答辩 8），16 周 × 每周 4 学时

---

## 一、课程定位与性质

### 1.1 课程定位

本课程以真实落地的「**连锁餐饮智能体工程化项目**」（支撑百万用户、DAO 10 万、在线 2 万、API 5-10K QPS、LLM 50-200 QPS）为教学载体，是人工智能应用技术专业**面向产业一线的综合性项目实践课**。课程不是简单的知识罗列，而是**按照软件工程全生命周期**（立项 → 数据评估 → 架构 → 编码 → 测试 → 压测 → 部署 → 运维 → 复盘）还原一个真实企业级 AI 项目的**完整死亡与重生路径**。

课程基于一份真实的失败复盘——《我最惨的 AI 项目复盘：从签单 120 万到退款、道歉、重来》，让学生**先从别人踩过的坑里学会如何不踩坑**，再亲手把项目重做一遍。

### 1.2 课程性质

| 项目 | 说明 |
|---|---|
| 课程性质 | 专业核心课 / 项目实践课 |
| 开设学期 | 第 4 或第 5 学期 |
| 前导课程 | Python 程序设计、JavaWeb、数据库原理、机器学习基础 |
| 并行课程 | 大数据技术、云计算与容器化、软件测试 |
| 后续课程 | 顶岗实习、毕业设计、岗位综合实训 |

### 1.3 课程面向岗位

| 岗位 | 典型工作任务 | 本课程支撑的能力 |
|---|---|---|
| AI 应用开发工程师 | 智能体/GPT 应用开发、提示词工程、RAG | 智能体开发、语义检索、工具调用 |
| 大数据开发工程师 | 数据资产评估、数据仓库、数据治理 | 数据质量核验、读写分离、亿级数据 |
| 软件测试工程师 | 功能/性能/压力测试、自动化测试 | pytest/JUnit、K6/Locust 压测 |
| 云原生运维工程师 | 容器化、K8S 部署、监控告警、CI/CD | Docker + K8S + Prometheus |
| Java/Python 全栈工程师 | 微服务、GraphQL、消息中间件 | SpringBoot/Litestar、Pulsar |

## 二、课程目标

### 2.1 总体目标

以「**工程化的方式交付一个稳定、可压测、可复盘的 AI 智能体项目**」为总目标，培养学生**从 0 到 1 完整落地企业级 AI 项目**的工程能力、**数据要敏感**的数据资产意识、**测试先行**的质量意识，以及德国双元制所强调的**学校与企业双场所、理论技能双手证**的复合职业素养。

### 2.2 素质目标（德育/职业素养）

1. 树立**职业诚信**：不夸大数据、不"樱桃数据"、只承诺业务结果（对应反模式 P2/P6）；
2. 培养**工程敬畏**：签约前做数据评估、分阶段交付（对应反模式 P1/P3）；
3. 强化**用户体验与审美**：能给智能体产品设计可用的管理界面（高级美工视角）；
4. 养成**复盘文化**：项目出问题留痕、归档 ADR、迭代优化；
5. 具有**双元制职业行动力**：能独立承担任务、主动协调、规范交付。

### 2.3 知识目标

1. 掌握 TOGAF 架构方法论与 DDD 领域驱动设计核心思想；
2. 掌握智能体（Agent）关键技术：Harness、工具调用、RAG、语义缓存、世界模型；
3. 掌握 MCP 模型上下文协议与 A2A 智能体互操作协议；
4. 掌握多级缓存、读写分离、消息中间件、图数据库等大数据架构原理；
5. 掌握 TDD/BDD/SDD 测试驱动开发方法；
6. 掌握 K6/Locust 压测原理与性能分析方法；
7. 掌握容器化与 K8S 部署运维基本方法。

### 2.4 技能目标

1. 能针对一个真实业务写出百万级口径的需求与架构方案；
2. 能用 Java21+SpringBoot、Python+LangGraph/Litestar 开发微服务与智能体；
3. 能使用 GraphQL BFF、TiDB 读写分离、Caffeine/Redis/Milvus 多级缓存；
4. 能实现 Agent Harness（预算/上下文/循环/评估）、MCP 工具、A2A 卡片；
5. 能用 pytest/JUnit/Gherkin 编写并跑通测试，报告通过率；
6. 能用 K6+Locust 做功能/性能/压力测试，输出测试报告与优化建议；
7. 能用 Docker/K8S 部署服务，编写 yaml 与运行脚本；
8. 能把 md 工程文档转换成 Word/PDF 等可交付格式。

### 2.5 与三种教学法的映射（贯穿全课程）

| 教学法 | 应用方式 | 对应内容 |
|---|---|---|
| **德国双元制** | 学校（理论/仿真实训室）与企业（真实项目/岗位任务）双场所交替；一周在校、一周下企业；"双元"主体为学校+企业，双场所、双教师的"教+练+用+评"闭环 | 15 节理论课（校内）+6 项企业实践任务（企业导师指导）交替排布；企业实践占 32 学时 |
| **费曼学习法** | 每节课设"费曼 5 分钟"：学生用自己的话复述知识点，讲给同学听；对上不了台，用"费曼图谱"书面输出；以"能否讲清楚"检验是否真懂 | 每课时末的费曼输出作业 08 目录、课堂随堂复述 |
| **布鲁姆认知模型** | 习题与任务按 记忆→理解→应用→分析→评价→创造 六层梯度设计；项目从"会复述"到"会创造新系统"逐层进阶 | 09 布鲁姆分层题库、实训任务书、答辩评价 |

## 四、课程内容与要求（知识点清单）

### 4.1 模块 A：工程方法与需求（U01-U02，8 学时）

- A1 软件工程全过程、国家标准 GB/T 8557 / GB/T 25000 / DCMM
- A2 AI 项目七大反模式（P1-P7）：签约前数据评估、只承诺业务结果、分阶段交付、透明交付、禁樱桃数据、数据依赖声明降级、一品一码+别名+单位字典
- A3 百万级口径：100 万注册 / 10 万 DAO / 2 万在线 / API 5-10K QPS / LLM 50-200 QPS
- A4 需求规格说明书、用例建模、验收标准

### 4.2 模块 B：架构与技术选型（U03-U05，12 学时）

- B1 TOGAF ADM 四个架构域（业务/数据/应用/技术）
- B2 领域驱动设计 DDD：六边形/整洁架构、限界上下文、CQRS
- B3 GraphQL BFF、网关
- B4 技术选型：Java21+SpringBoot3（弃 Tomcat 用 Undertow）、Python Litestar（弃 FastAPI/Granian）、Vue3
- B5 数据：TiDB HTAP 读写分离、Caffeine/Redis/Milvus 多级缓存 L0-L4、Redis 集群与 warmup
- B6 中间件：Pulsar 消息队列、Ollama/LiteLLM 推理

### 4.3 模块 C：数据资产与智能体开发（U06-U11，24 学时）

- C1 Phase0 数据资产评估、数据质量 9 项核验、亿级数据生成
- C2 智能体 Harness：Budget 预算 / Context 上下文 / Loop 循环 / Eval 评估
- C3 RAG 与语义缓存、防幻觉三件套（工具直答+数字溯源+数值守卫）
- C4 MCP 模型上下文协议（Streamable-HTTP）、工具开发
- C5 A2A 智能体互操作（AgentCard、message/send）
- C6 世界模型：统计仿真与预测（灵敏度/蒙特卡洛）
- C7 事件驱动、领域事件、Pulsar 生产者/消费者

### 4.4 模块 D：测试、部署与运维（U12-U14，12 学时）

- D1 功能测试：用例设计、43 用例六域、缺陷管理
- D2 性能测试：K6 七场景、Locust 混合旅程、全梯度（50~10 万并发）
- D3 容器化 Docker、K8S 部署 yaml、CI/CD、监控 Prometheus/Grafana/Loki

### 4.5 模块 E：综合集成与交付（U15-U16，8 学时）

- E1 多视角审查（招标/前端/架构/AI/美工）、打分与重构
- E2 ADR 架构决策记录、版本管理（V1→V2）
- E3 文档交付：md→Word/PDF、Git、CI
- E4 答辩汇报、复盘总结

## 五、考核与评价方案

### 5.1 考核原则

采用**过程性考核 + 终结性考核**结合、**双元制双主体评价**（企业导师 + 校内教师）的多元评价；杜绝一纸期末定论。

### 5.2 成绩构成（总分 100）

| 维度 | 权重 | 考核内容 | 评价主体 |
|---|---|---|---|
| 平时表现 | 10% | 出勤、课堂参与、费曼复述表现 | 校内教师 |
| 实训任务 | 30% | 6 项企业实践任务（06 任务书评分） | 企业导师 60% + 教师 40% |
| 阶段项目 | 25% | 个人/小组阶段性成果（架构、模块、测试） | 校内教师 |
| 期末项目答辩 | 25% | 完整项目交付 + 答辩（双元制成果） | 企业+校内双评委 |
| 双语文档/作品集 | 10% | 工程文档（Word/PDF）、费曼输出、布鲁姆题解 | 校内教师 |

### 5.3 布鲁姆分层评价指标

| 层级 | 指标描述 | 对应分钟 |
|---|---|---|
| 记忆 | 能说出概念、术语、协议名称 | 随堂问答 5% |
| 理解 | 能用自己的话解释架构原理 | 费曼复述 15% |
| 应用 | 能按模板写出代码/配置/用例 | 实训 30% |
| 分析 | 能分析性能数据、缺陷根因 | 压测报告 15% |
| 评价 | 能评审方案、打分、选型 | U15 审查报告 10% |
| 创造 | 能设计并实现新的智能体功能 | 期末项目 25% |

### 5.4 技能证书对标（可选）

对接 1+X 云计算平台运维与开发、人工智能应用工程化（初级/中级）职业技能等级证书。

## 七、课程特色与创新

1. **复盘反哺教学**：用真实"死亡项目"培养工程敬畏，先学失败再学成功；
2. **双元制落地**：理论在做中学、实践在做中学，学校企业双场所双导师；
3. **费曼输出驱动**：每课"费曼 5 分钟"，以教代学；
4. **布鲁姆梯度进阶**：习题/任务从记忆到创造逐层递进，因材施教；
5. **百万级真实工程**：数据集 1.34 亿行、压测 10 万并发，接轨产业真实强度；
6. **全链路交付**：课程结束即产出可演示、可压测、可部署的完整智能体项目。

## 八、课程实施基本要求

1. 双元制场所：校内实训机房（每人 1 机位）、合作企业项目现场（每学期≥6 次）；
2. 企业导师与校内教师共同授课、共同考核；
3. 每单元采用"讲授→演示→实训→费曼复述→布鲁姆练习→作业"六环节；
4. 提供 Git 同步机制，学生随时拉取最新课程资料。
